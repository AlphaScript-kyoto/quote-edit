## 1. このアプリは何をするか

SoftBank 法人向けのローカル完結型見積PDF一括作成ツールです。

1. 「機種代金一覧表」フォルダ内の価格表PDFを読み取る
2. 販売区分・斜金プラン・データ容量・おうち割・IPS・安心サポートなどの組み合わせで見積を生成する
3. `output/見積PDF/` 配下に固定ルートで上書き／追加保存する

PDFは縦向きA4・原則1ページです（横向きレイアウトは採用しません）。

## 4. `.cursor` フォルダとは（詳細）

### 4.1 一言で

**Cursor（開発用AIエディタ）が、このリポジトリで作業するときに読む「社内ルール置き場」**です。
見積PDFの計算・生成・配布EXEの動作には**一切関与しません**。

### 4.2 なぜ置くか

| 目的 | 説明 |
|------|------|
| 引き継ぎ | 後任や別セッションのAIが、毎回ゼロから仕様を推測しなくてよい |
| 事故防止 | 出力ルート変更などの退行をルールで抑止 |
| ドキュメント誘導 | 深い仕様は AI_CONTEXT / 本仕様書へ誘導し、ルール本体は短く保つ |

### 4.3 中身

| パス | 役割 |
|------|------|
| `.cursor/rules/quote-edit-handoff.mdc` | `alwaysApply: true`。このワークスペースでのAI会話に常時注入されるルール |

`.mdc` は Markdown + 先頭の YAML フロントマターです。

- `description` : Cursor上の説明文
- `alwaysApply: true` : 常に適用
- あるいは `globs` : 特定ファイル編集時のみ適用

### 4.4 開発者が守ること

1. 勝手に削除しない（掃除で消すと次のAIが方針を見失う）
2. 仕様のハードルールが変わったら `.mdc` も更新する
3. 長い設計説明は `.mdc` に書き切らず、本仕様書 / `AI_CONTEXT.md` に書く
4. 現場向け `README.txt` には「触らなくてよい」程度の短い説明だけ残す
5. 配布用 `portable/` に `.cursor` が入っていなくてもよい（ソース側にあれば十分）

### 4.5 他ドキュメントとの関係

```
現場ユーザー     → README.txt（.cursorは触れなくてよい、と一言）
後任開発者       → 本仕様書（このセクション）
Cursor / AI      → AGENTS.md + AI_CONTEXT.md + .cursor/rules/*.mdc
```

英語のAI向け文書では、セクション名 **Cursor project config** に同等の説明があります。

## 7. ビジネスルール要約（ver.1.1）

- 出力先固定: `output/見積PDF/`
- 除外機種は全機種再生成より強い。個別見積一覧にも出ない
- おうち割ありでは 5GB を作らない
- IPS一括は lump / monthly_as_running があり得る
- 安心サポートは SoftBank とは別請求（株式会社インフィニティ）
- PDFは縦向き・原則1ページ

## 11. 1.3 / 1.3.1 以降で後から足した要点（詳細は AGENT_CHANGE_HISTORY）

- 手数料デフォルトは特別対応 3000（`special_3000`）。標準事務手数料は任意フラグ `include_standard_initial_fee`
- 旧チェックポイントの `include_special_initial_fee` は互換用マッピングあり
- IPS通常（一括）パターンは一括既定オフ
- 除外UI表記は「除外する機種」。全機種強制再生成より除外が強い
- PDF（1.3.1）: No.列、月額はユニバーサルを合計直前、値引きは赤字、表題枠なし、`{販売区分}お見積り`、TEL/FAX1行
- AQ など部署の実住所・電話は **`company.json`（Git 対象外）** のみ。リポジトリには `company.example.json` のみ
- 配布用 README・リリースノートは **UTF-8 BOM**。中身が全部 `?` ならファイル破損（ZIPのせいだけと思わない）

以上が ver.1.1 骨格 + 後追い追記です。細部・セッション単位の記録は `AGENT_CHANGE_HISTORY.md` に追記し続けてください。
